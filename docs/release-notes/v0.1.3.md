# v0.1.3 — Delivery Observability Maintenance

> **Status: released 2026-11-26.**

Cairn is a local-first, deterministic experience retrieval layer for AI coding
agents. v0.1.3 makes the path from retrieval to delivery visible and fixes a
session-bookkeeping defect. It does not change the retrieval algorithm or claim
a task-outcome improvement.

## Try it in 30 seconds

```bash
git clone https://github.com/mokuyoaxis/cairn.git
cd cairn
git checkout v0.1.3

python3 cairn.py --version
CAIRN_HOME=./examples python3 cairn.py recall "docker compose config 密钥"
CAIRN_HOME=./examples python3 cairn.py explain "docker compose config 密钥"
CAIRN_HOME=./examples python3 cairn.py trace "docker compose config 密钥"
CAIRN_HOME=./examples python3 cairn.py trace \
  "docker compose config 密钥" --json --payload
```

The example may write only to the gitignored `examples/cache/` and
`examples/log/`. Trace itself does not write logs or update session state.
Keep `cairn_trace.py` beside `cairn.py`; the new command is a thin core entry
backed by that standard-library-only module.

## What you get

- **End-to-end delivery explanation.** Trace follows retrieval, Experience
  Contract and declared-scope admission, the three gates, session deduplication
  and rendering. It distinguishes `ineligible`, `out_of_scope`,
  `low_score`, `low_cover`, `low_margin`, `over_limit`,
  `already_delivered`, `truncated` and `budget_omitted`.
- **A prospective, not asserted, output.** `would_emit` describes what the
  current hook path would render. `host_receipt: not_observed` is explicit:
  trace does not invoke a host or model and cannot prove delivery to either.
- **Correct session bookkeeping.** Only cards actually rendered and successfully
  emitted are added to `seen`. A card omitted by the render budget, a rendering
  failure or an output failure does not consume its future delivery opportunity.
  Previously delivered cards still deduplicate within the same session.
- **Local and read-only diagnosis.** Trace uses the same retrieval, gate and
  rendering functions. It makes no network calls, writes no query/inject/miss
  logs and does not update `seen`. Like other retrieval commands, it may
  rebuild the disposable index cache. JSON omits raw query text, raw session IDs
  and the seen list, but candidate IDs and prospective card text may still be
  sensitive; trace is not a sanitization tool.

## Measured regression baseline

| Check | Observed result |
|---|---|
| Unit tests | **242 passing** — 139 core + 103 research fixtures |
| Seed retrieval eval | 80 positive / 60 negative queries on 12 entries |
| Recall@1 / Recall@3 | **75/80 = 93.8%** / **80/80 = 100%** |
| Injection@1 / Injection@3 | **58/80 = 72.5%** / **58/80 = 72.5%** |
| False injection | **2/60 = 3.3%** |
| Average injection | 136 chars/query; 188 chars per actual injection (58/80) |
| Contract admission eval | **3/3 cases** |
| Trust & applicability eval | 13 cases; hard failures 0; four known gaps remain |
| Core budget | `cairn.py`: **1,200 lines**; zero third-party dependencies |
| Syntax compatibility | Python 3.9 AST parse passes; CI covers Python 3.9 and 3.12 |

These are regression measurements on the seed fixture, not a general-purpose
benchmark, production success rate or security guarantee. Historical hook latency
samples are not remeasured for this release.

## What was studied and deliberately not imported

The delivery work follows the isolated lab's render/dedupe boundary experiments
and its distinction between gold retrieval, actual output and host receipt. The
main implementation was independently written and tested against the released
core; the lab branch was not merged. See the existing sanitized
[retrieval boundary notes](../research/experience-retrieval-boundaries-2026-10.md).

This release does not import lab threshold recalibration, tokenizer changes,
query logging, alias expansion, doc2query, multi-card selection or private
corpora. It also does not remove storage paths from rendered cards; the existing
card format remains `name + summary + relative path`.

## Known limitations

- Retrieval thresholds remain hand-tuned on a small fixture; no calibrator is
  included. Synonym and long-prompt limitations remain.
- `verified` is self-declared metadata, not cryptographic proof. Scope gates
  only when declared, `verified_at` does not expire automatically, and
  conflicts are not detected.
- Cards are retrieval hints, not full text; long summaries may lose conditions
  or paths. Trace exposes clipping and budget omission but does not repair them.
- Trace predicts local hook output. It does not observe real host/model input,
  context compaction, concurrent state updates or downstream task success.
- The JSON schema `cairn.trace/v0` is new and should be treated as provisional
  within the experimental 0.x series.
- The existing trust eval still reports four known gaps: stale, undeclared-scope,
  conflict and malicious-summary cases. Passing the hard checks does not remove
  these limitations.

## 中文摘要

**2026-11-26 已发布。**

Cairn v0.1.3 是交付可观测性维护版本，新增只读 `cairn trace`，依次解释
检索、契约与声明 scope 准入、三道门、会话去重和渲染。它能区分低分、低覆盖、
领先幅度不足、已交付去重、预算省略和首卡截断。`--json --payload` 可输出
机器可读轨迹和预计 Hook payload；`would_emit` 只是预计输出，
`host_receipt: not_observed` 明确表示未验证真实宿主或模型接收。

同时修复会话去重记账：只有实际渲染并成功输出的卡才写入 `seen`；预算省略、
渲染失败或输出失败的卡仍可在后续重试，已实际交付的卡仍按会话去重。
Trace 不写日志、不更新会话、不联网，但可像其他检索命令一样重建派生缓存。
JSON 不保存原始 query、原始会话 ID 或 seen 清单，但候选和预计卡片文本仍可能敏感，
它不是脱敏工具。

实测回归：242 项测试通过（139 核心 + 103 研究夹具）；12 条种子库上 80 正例、
60 负例，召回@1 为 75/80、召回@3 为 80/80、注入@1/@3 均为 58/80、误触发为 2/60。
契约准入 3/3；信任与适用性 13 例硬失败 0，4 个已知缺口仍存在。核心 1200 行，
零第三方依赖；Python 3.9 AST 检查通过。以上是回归结果，不是任务成功率或安全保证。

本版没有合并 lab 分支，也没有引入其实验阈值、分词、查询日志、别名、doc2query、
多卡选择或私有语料。卡片仍保留现有“名称 + 摘要 + 相对路径”格式。部署时需将
`cairn_trace.py` 与 `cairn.py` 放在一起。
