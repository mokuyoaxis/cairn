# v0.1.2 — Candidate Admission Maintenance

> **Status: released 2026-11-06.**

Cairn is a local-first, deterministic experience retrieval layer. v0.1.2 is a
maintenance patch for the v0.1.1 baseline. It fixes one candidate-selection defect
and publishes the sanitized research records that motivated the change.

## Try it

```bash
python3 cairn.py --version
python3 -m unittest discover -s tests -q
```

## What changed

- The hook, recall and explain paths now pass the full scored candidate pool to
  the gate. Contract-ineligible and scope-mismatched entries no longer consume the
  candidate budget before eligible entries are considered.
- Added regression tests for hook, recall and explain, covering unverified peers
  and declared-scope mismatches.
- Published two sanitized research notes: retrieval boundaries and long-task
  prompt length.

## What did not change

- The Experience Contract, three score gates, declared-scope semantics and hook
  output format are unchanged.
- No new command, field, dependency, network path or host adapter.
- The research notes are observations, not roadmap commitments.

## Verification

- Unit tests: **230 passing** (127 core + 103 research fixtures).
- Retrieval eval: 80 positive / 60 negative; recall@1 93.8%, recall@3 100%,
  injection@1/@3 72.5%, false injection 3.3%.
- Contract admission eval: 3/3.
- Trust & applicability eval: 13 cases; hard failures 0; four known gaps remain.
- Hook cold-start p95: 74.2 ms at 12 entries and 98.5 ms at 1,000 synthetic
  entries (30 runs each, single-machine sample).
- Core: 1,200 lines; zero new dependencies; Python 3.9 AST parse passes.

## Known limitations

The v0.1.1 limitations remain unless explicitly fixed here. In particular,
long task prompts can dilute query-term coverage, the fixed margin threshold is
calibrated on a small library, cards are retrieval hints rather than full text,
verified is self-declared, scope gates only when declared, verified_at does not
expire automatically, and conflict detection is not implemented.
