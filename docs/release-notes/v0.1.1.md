# v0.1.1 — Index Revocation Maintenance (DRAFT — release pending)

> **Status: implementation complete on release/0.1.1; release not yet cut.**
> Do not tag or publish until the version is bumped, the final measurements are
> confirmed, and the DRAFT marker is removed.

Cairn is a local-first, deterministic experience retrieval layer. v0.1.1 is a
maintenance patch for the v0.1.0 baseline. It fixes one cache-invalidation defect
and adds regression coverage; it does not add a feature or change the product boundary.

## What changed

- The index cache signature now includes each entry's content SHA-256 in addition
  to its name, mtime, size and ctime. An entry changed from active to archived is
  rebuilt even when the file keeps the same size and mtime.
- get_index() revalidates the current signature before reusing an in-memory index.
- The disk cache is rejected and rebuilt when the signature no longer matches.
- Two regression tests cover the warm-index and cold-cache paths.

## What did not change

- The Experience Contract, gates, scope semantics and hook output are unchanged.
- No new command, field, dependency, network path or host adapter.
- Candidate-pool starvation, card truncation, context redelivery, conflict
  adjudication, evidence lineage, fact binding, timeout semantics and phase
  triggers remain out of scope for this patch.

## Verification

- Unit tests: **226 passing** (123 core + 103 research fixtures), no expected failures.
- Retrieval eval: 80 positive / 60 negative; recall@1 93.8%, recall@3 100%,
  injection@1/@3 72.5%, false injection 3.3%.
- Contract admission eval: 3/3.
- Trust & applicability eval: 13 cases; hard failures 0; four known gaps remain.
- Hook cold-start p95: 77.0 ms at 12 entries and 106.0 ms at 1,000 synthetic entries
  (30 runs each, single-machine sample).
- Core: 1,200 lines; zero new dependencies; Python 3.9 AST parse passes.

## Known limitations

The v0.1.0 limitations remain unless explicitly fixed here. In particular,
verified is a self-declared state, scope gates only when declared, verified_at
does not expire automatically, conflict detection is not implemented, and the
cache signature check still has a TOCTOU window between hashing and use.
