# 安全与信任边界

Cairn 是一个**本地工具**，不是安全边界本身。本文描述它已经做了什么、没做什么，以及公开/共享前必须人工检查什么。

> Cairn 不宣称解决 Prompt Injection，也不替代宿主 Agent 的权限、沙箱和危险操作审批。

## 0. 摘要

### 0.1 声明与状态

| 声明 | 状态 |
|---|---|
| 运行时只读，不执行条目命令 | 已实现 |
| 默认不联网 | 已实现 |
| 日志不落原始 prompt/session | 已实现 |
| audit 覆盖 entries/log/session/cache | 已实现 |
| sanitize 拒绝写源库/默认不覆盖 | 已实现 |
| 导入/未验证条目 quarantine | 近期目标，尚未 ship |
| 显式 trust/verified_at/status 契约 | 近期目标，尚未 ship |
| 宿主权限、沙箱、危险操作审批 | 宿主责任，不是 Cairn 边界 |
| 解决 Prompt Injection | **不宣称** |

## 1. 信任模型

### 经验是证据，不是指令权威

注入卡片属于**低信任参考内容**。它不能：

- 覆盖系统、开发者或用户指令；
- 自行扩大 Agent 的工具权限；
- 要求泄露密钥、执行任意命令、绕过验证；
- 把历史结论包装成当前事实。

宿主 Agent 必须继续执行自己的指令隔离、权限控制和工具审批。Cairn 不替代这些机制。

### 来源、验证与生命周期（近期契约目标）

- 条目应明确区分 `source`（来源）、`verified_at`（验证依据/时间）、`scope`（适用范围）与 `status`（active/deprecated/archived）。
- 信任状态至少区分 verified / unverified / quarantined；导入经验默认 quarantine，人工审阅后才 active。
- **人工批准不等于技术验证；近期验证不等于跨项目适用。**
- 默认只让 active + verified 的条目参与自动注入；不满足准入条件的条目可以被显式搜索，但不自动进入上下文。

### 两种失败策略

| 场景 | 策略 | 行为 |
|---|---|---|
| Hook 检索增强 | fail-open | 异常/坏索引/坏 stdin 时静默 exit 0，不阻断任务，不注入不可信内容 |
| 写入/校验/脱敏 | fail-closed | 路径、数据、原子写入失败时返回非零，不假装成功 |

## 2. 运行时

- 正常 Hook 检索链路只读：不新增/修改/删除经验，不执行经验中的命令，不访问不必要的工作空间文件。
- Hook 只在 `UserPromptSubmit` 读取 stdin JSON，输出平台协议 JSON；异常静默返回 0。
- 去抖状态写在 `log/session-*.json`，内容只含已注入条目名与时间戳；文件名使用清洗后的会话标识（**不是哈希**，属于已知隐私缺口，后续考虑哈希），不含 prompt。
- 默认不联网：检索、统计、校验都不发起网络请求。

运行时允许写 `cache/index.pkl` 和日志/会话文件；这些是运行时状态，不是经验资产。

## 3. 数据与日志

### 数据目录

```text
$CAIRN_HOME/
├── entries/      # 经验正文；需要备份的唯一目录
├── log/          # 事件日志、会话去抖
└── cache/        # 派生索引，可删除
```

### 日志默认不落原始 prompt

默认日志只记录：

- UTC 时间；
- 事件类型；
- 会话指纹（不是原始 `session_id`）；
- 命中条目 ID；
- 门控原因；
- `query_sha256` / `query_len`；
- `note_sha256` / `note_len`（feedback）；
- 结果数量、分数等必要元数据。

不记录原始 prompt、原始 session ID、原始 feedback note。

需要调试预览时：

```bash
CAIRN_LOG_QUERY_PREVIEW=1 ...
```

开启后只额外记录**先脱敏、再截断到 120 字符**的预览。它仍是敏感数据，分享日志前必须人工检查。

### 旧日志

加固前版本的日志可能已经包含原始 prompt。新版本不会自动清理旧文件。

建议：

```bash
CAIRN_HOME="$HOME/.cairn" python3 cairn.py audit
```

`audit` 会把日志中的凭据/邮箱/路径标出来（输出本身做了脱敏）。确认后人工轮转或删除 `log/*.jsonl`；不要直接分享 `log/`。

## 4. `audit`

扫描范围：

- `entries/*.md`
- `log/*.jsonl`
- `log/session-*.json`
- `cache/index.pkl`（派生数据）

检查项：

- 私钥块；
- 云/平台凭据（`AKIA...`、`ghp_...`、`gho_...`）；
- `sk-` API key；
- Bearer token；
- 邮箱；
- 含用户名的绝对路径（Windows / Linux / macOS）；
- 内网 IP；
- 业务数字。

行为：

- `critical` / `high` 返回 1；
- 仅 `medium` 返回 0 但提示；
- 输出只显示脱敏样本（如 `<api-key>`、`<email>`、`/home/<user>`）；
- 文件读不出时返回非零，不把“读失败”当 PASS；
- 空库/错误 `CAIRN_HOME` 直接返回 1，不把“0 个文件”当 PASS。

限制：正则只能覆盖已知形态；编码、拆分、拼接、图片/二进制中的秘密可能漏检。`audit` 是体检，不是保证。

## 5. `sanitize`

```bash
python3 cairn.py sanitize --out /tmp/cairn-clean
```

行为：

- 生成 `/tmp/cairn-clean/entries/`，不修改源库；
- 拒绝输出目录等于或位于源 `entries/` 内（含符号链接解析后的路径）；
- 拒绝目标路径落在源 `entries/` 内；
- 默认拒绝覆盖已有目标；`--force` 显式覆盖；
- 先读入全部源条目、替换后再写；单文件使用临时文件 + 原子替换；
- 替换路径/邮箱/业务数字，以及私钥、云凭据、API key、Bearer。

验证输出：

```bash
CAIRN_HOME=/tmp/cairn-clean python3 cairn.py audit
```

限制：

- 文本替换是**尽力而为**，可能误伤正常内容，也可能漏掉变体；
- 不能替代人工复核；
- 不会自动删除源库中的原始日志；
- 不能保证输出适合公开；发布前仍需人工审阅。

## 6. 经验注入风险

经验库可能包含恶意/污染内容，例如：

- 伪造系统指令；
- 诱导忽略安全规则；
- 要求读取密钥或执行无关命令；
- 冒充开发者/用户授权；
- 通过 Markdown/路径诱导读取外部文件；
- 在 summary 中夹带可执行指令。

当前缓解：

- 卡片只包含 name/summary/path，不自动执行；
- 运行时只读；
- 经验被定位为低信任参考内容；
- `audit` 可发现部分敏感内容。

仍需补：

- 恶意经验测试集；
- 注入内容的静态检测/提示；
- 宿主侧指令隔离与权限控制的端到端验证；
- 冲突经验处理与失效标记。

**静态扫描不能代替宿主 Agent 的权限控制。**

## 7. 网络与外部服务

- 当前版本默认零网络。
- 未来若引入模型判断、同步、在线服务，必须是显式 opt-in 的可替换扩展，不能成为核心依赖。
- 不应把任何第三方判断服务作为默认运行依赖。

- [ ] 源码、文档、示例、eval 数据无真实密钥/邮箱/敏感路径；
- [ ] Git 历史也扫描过，不只看当前工作区；
- [ ] `CAIRN_HOME=... cairn lint`、`eval`、`audit` 通过；
- [ ] 旧日志已审计/轮转；
- [ ] `sanitize` 输出经过人工复核；
- [x] 本项目许可证已确定：MIT（Copyright (c) 2026 Messia）；
- [ ] 所有第三方参考材料的许可证/署名义务已核对；
- [ ] 至少一个真实宿主完成端到端 Hook 验证；
- [ ] README、CLI 帮助与真实行为一致；
- [ ] 失败模式（空库、无命中、坏索引、无权限、路径冲突）有说明。

## 9. 已知缺口

- `audit` 是正则扫描，不覆盖所有编码/变形；
- 会话去抖文件名仍使用清洗后的 session 标识，而不是哈希；敏感 session ID 场景需要随机化或后续修复；
- 经验库没有签名/来源验证机制；
- 没有恶意经验测试集；
- 没有写入生命周期（deprecated/archived）与冲突检测；
- 没有对 Hook 宿主协议的跨平台端到端安全测试；
- 第三方参考材料的许可证/署名义务尚未完成发布前核对。

安全问题和普通 bug 一样，需要可复现步骤、影响范围和回归测试；不要用“静默通过”掩盖失败。
