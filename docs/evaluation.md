# 评测

Cairn 的评测目标是**回归与适用性判断**，不是排行榜。当前样本很小，任何小数点后的差异都不应被当作稳定结论。

> 评测应同时回答三个问题：该出现的经验有没有出现；不该出现的经验有没有保持沉默；被注入的经验是否真的适用于当前任务。

## 0. 摘要

- 当前在 12 条示例库、24 条正例、25 条负例上做回归。
- 排序召回@3 为 100%，但注入@3 只有 75%：**找到 ≠ 注入**。
- 4.0% 负例仍被注入；安全评测需要单独覆盖恶意/过期/scope 不匹配内容。
- 平均注入长度仍有口径问题，不能当作正式成本承诺。
- 近期优先建设 **Trust & Applicability Eval**，而不是只扩大 Recall。

## 1. 当前评测集

| 文件 | 内容 | 数量 |
|---|---|---|
| `eval/queries.jsonl` | 用户口吻的正例；每行 `query` + `expect` | 24 |
| `eval/negatives.jsonl` | 与经验库无关的负例；每行 `query` | 25 |
| `examples/entries/` | 评测所用示例经验库 | 12 |

正例示例：

```json
{"query":"compose 一执行就把密码打出来了","expect":["config-dump-reveals-secret-values"]}
```

`expect` 可以包含多个可接受条目；排序中第一个命中的位置用于计算 rank。

## 2. 指标定义

### Retrieval（排序质量）

- **Recall@1**：正确条目是否排第 1；
- **Recall@3**：正确条目是否在前 3；
- **MRR**：第一个正确条目的倒数排名平均值。

这些指标回答“检索本身有没有找到”。

### Injection（真实进入上下文）

- **Injection@1 / @3**：过门控后真正会注入的卡片里，是否包含正确条目；
- **False Injection Rate**：无关负例中，仍然注入了卡片的比例；
- **Correct Abstention**：没有相关经验时保持沉默的比例（当前未单独报告）；
- **平均注入长度**：卡片字符数/估算 token 数。

这些指标回答“产品行为有没有把经验真正端到 Agent 面前”。

### Applicability / Outcome（尚未系统评测）

- 经验是否适用于当前项目、版本、工具行为；
- 是否改善任务成功率、减少可预防错误；
- 是否造成伤害（错误经验、过时经验、上下文冲突）。

当前没有 Level 3/4 的稳定评测，不能声称“Cairn 提升了 Agent 任务成功率”。

## 3. 当前结果

在 12 条示例库上，默认门槛（注入@3 ≥70%，误触发 ≤10%）：

| 指标 | 数值 |
|---|---|
| 召回@1 | 91.7% |
| 召回@3 | 100% |
| MRR | 0.958 |
| 注入@1 | 75.0% |
| 注入@3 | 75.0% |
| 负例误触发 | 4.0%（1/25） |
| 平均注入（每 query，未注入计 0） | 145 字符 ≈ 73 tokens |
| 平均注入（每次实际注入） | 194 字符 ≈ 97 tokens（18/24 次） |
| 单元测试 | 58 项，全绿 |
| hook p95（本机） | 约 70ms |

解释：

- 召回@3 100% 只说明“正确条目在候选前 3”，不等于会注入；6/24 条最终没有卡片进入上下文。
- 注入@3 75% 是当前产品行为，不一定是 bug；需要看具体 query 是“确实不该注入”还是“门控误伤”。
- 4% 误触发来自一条明显通用编程问题（“写一个函数判断字符串是不是回文”）；值得后续分析命中词与阈值，而不是只接受这个数字。

## 4. 口径说明（2026-10-19 已修正）

### 4.1 `eval --min-margin` 已透传

`cairn eval` 现在把 `--min-margin` 传给正例与负例的 `gate` 调用；回归测试覆盖“默认通过、`--min-margin 99` 不注入”的对照。

历史问题（已修复）：此前 `cmd_eval` 未传该参数，eval 始终使用默认 1.5，第三道门在 eval 中失效。

### 4.2 平均注入口径已修正

历史问题（已修复）：旧实现会对每条正例都调用 `render_cards(gate(...))`；gate 为空时仍返回标题+尾注约 **63 字符**，而真实 Hook 在无命中时输出 **0 字符**，导致旧数字偏高。

现在：

- 未注入的 query 计 **0 字符**；
- 同时报告「每 query 平均」与「每次实际注入平均」；
- 当前结果：145 字符/query；实际注入 18/24 次，194 字符/次（含卡片标题与尾注，不含平台 JSON 包装）。

这些数字仍是诊断值，不是成本承诺。

### 4.3 token 数是估算

代码按“2 字符 ≈ 1 token”粗略估算；中文在不同 tokenizer 下差异很大。需要精确预算时，用目标模型的 tokenizer 离线测量，并注明模型版本。

## 5. 如何运行

推荐在临时副本上跑，避免把 cache/log 写进仓库：

```bash
TMP=$(mktemp -d)
cp -a examples/. "$TMP"/
CAIRN_HOME="$TMP" python3 cairn.py eval
```

也可以直接跑：

```bash
CAIRN_HOME=./examples python3 cairn.py eval
```

`examples/cache`、`examples/log` 已 gitignore，但仍建议用临时目录做可复现实验。

退出码：

- `0`：注入@3 与误触发都过门槛；
- `1`：未过门槛；
- `2`：评测集不存在/参数错误。

## 6. 如何扩展评测集

1. 在 `eval/queries.jsonl` 增加 `{"query": "...", "expect": ["slug"]}`；
2. 在 `eval/negatives.jsonl` 增加真实但无关的请求；
3. 不要只对已有正例做同义句扩写；按任务族/经验来源划分，避免测试和训练共享几乎相同的措辞；
4. 新条目入库后，先跑 `lint`，再跑 `eval`；
5. 如果门槛不过，先判断是“检索没找到”还是“门控没注入”，再调参。

## 7. 后续评测计划

- **Trust & Applicability Eval（近期优先）**：覆盖恶意、过期、scope 不匹配、冲突、未验证/quarantine 条目；记录 Correct Abstention、Malicious/Stale Injection、错误交付，而不只是 Recall；
- **v0.2**：正例扩到 ≥80，补足挑战性负例；
- **v0.3**：扩到 150–200 条，覆盖跨项目/版本/冲突/过时经验；
- **规模实验**：12 / 100 / 500 / 1000 / 5000 条，记录 p50/p95/p99、内存、注入率、误注入率；
- **真实 Agent 对照**：No Memory / Manual Recall / Automatic Cairn 三组，同任务、同库、同模型、同权限、同预算；
- **消融**：无门控 vs 有门控、有 Margin vs 无 Margin、summary vs summary+scope、1 条 vs 最多 3 条、全文 vs 卡片、去抖开关。

在没有真实任务对照之前，不应把“召回@3 100%”当成“Cairn 有用”的证据；也不能靠“全部拒绝”获得漂亮的安全指标。
